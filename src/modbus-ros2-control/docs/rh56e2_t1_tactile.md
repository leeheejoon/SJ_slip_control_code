# RH56E2 T1 촉각 데이터 수신

RH56E2 V1.0.0 설명서 표 56의 압저항식(T1) 데이터 영역을 읽는다.
T2 정전용량식에는 사용할 수 없다. 실제 장치의 펌웨어 및 응답 해석은 실측 검증 필요.
기존 `FORCE_ACT` 및 `/joint_states`와 별도 데이터다. hand_command_node는 수정하지 않았다.

## 실행

기존 실행을 종료한 뒤 새 터미널에서:

```bash
source /opt/ros/jazzy/setup.bash
source ~/ros2_ws/install/setup.bash
ros2 launch rh56e2_control real.launch.py read_tactile:=true
```

주의: real.launch.py는 기존과 같이 컨트롤러 활성화 후 fsm_init_node를 실행한다.
촉각 수신 자체는 읽기만 수행하지만 이 launch의 기존 초기화 동작은 그대로 실행된다.
동일 시리얼 포트를 여는 두 번째 드라이버를 동시에 실행하지 않는다.

```bash
ros2 topic list -t | rg /hand/tactile
ros2 topic echo /hand/tactile/index_tip --once --qos-reliability best_effort
ros2 topic hz /hand/tactile/index_tip --qos-reliability best_effort
```

`read_tactile` 기본값은 false다. 켜면 토픽 발행자는 생성되지만, 유효한 장치 응답이
완료되어야 메시지가 발행된다. 토픽 목록에 나타나는 것만으로 수신 성공은 아니다.

## 메시지와 주소

토픽 형식: `/hand/tactile/<region>`, 타입 `sensor_msgs/msg/Image`.
`encoding=16UC1`, `is_bigendian=0`, 각 점의 값은 원시값 0..4095이며 N 단위가 아니다.
픽셀 k 값은 `data[2*k] + 256 * data[2*k+1]`이다.
header.stamp는 해당 부위의 마지막 청크를 받은 호스트 시각이며 센서 자체 시각이 아니다.
한 부위도 여러 청크를 순서대로 읽으므로 동시 측정 스냅샷을 보장하지 않는다.

| region | 시작 주소 | 배열 크기 |
|---|---:|---:|
| little_tip | 3000 | 3×3 |
| little_distal | 3018 | 12×8 |
| little_pad | 3210 | 10×8 |
| ring_tip | 3370 | 3×3 |
| ring_distal | 3388 | 12×8 |
| ring_pad | 3580 | 10×8 |
| middle_tip | 3740 | 3×3 |
| middle_distal | 3758 | 12×8 |
| middle_pad | 3950 | 10×8 |
| index_tip | 4110 | 3×3 |
| index_distal | 4128 | 12×8 |
| index_pad | 4320 | 10×8 |
| thumb_tip | 4480 | 3×3 |
| thumb_distal | 4498 | 12×8 |
| thumb_middle | 4690 | 3×3 |
| thumb_pad | 4708 | 12×8 |
| palm | 4900 | 8×14 |

명칭은 설명서의 부위 구분을 위한 것이다. 행·열은 수신 순서로 배열했으며 실제 표면의
좌표로 변환하지 않았다. 특히 손바닥은 설명서에 열 단위·역방향 행 순서가 명시되어
있으므로 압력 중심 계산 전에 좌표 매핑이 필요하다.

기존 드라이버의 Modbus 함수는 word 개수를 받으며, 설명서 주소는 byte 기준이다.
따라서 다음 청크 주소는 `region.address + 2 * word_offset`이다.
libmodbus가 반환한 word 값을 사용하며 실제 누름 실험으로 byte 해석을 검증해야 한다.

## 통신 주기와 실패 처리

일반 힘/각도 읽기와 명령 쓰기 뒤에 같은 스레드·같은 연결로 최대 96 word만 추가로 읽는다.
`tactile_period_ms`는 청크 완료 후 추가 대기 시간(기본 0 ms, 최저 0 ms)이다.
전체 1062점은 18청크이며 전체 순회에는 청크 대기와 힘/각도 통신 시간이 추가된다.
이는 데이터 경로 검증용이며 빠른 미끄러짐 제어용 샘플링 속도가 아니다.

읽기 실패 또는 4095 초과 값 수신 시 부분 프레임은 폐기하고 5초 후 같은 부위를 재시도한다.
실패 시 0값이나 이전 프레임을 새 데이터로 발행하지 않는다. 드라이버 재시작 시 읽기 상태를
초기화한다. 실제 수신·눌림 응답 확인 뒤 필요한 부위만 더 빠르게 읽도록 개선해야 한다.


## 촉각 분포 변화에 따른 추가 조임

`real.launch.py`는 기본적으로 `index_pad,middle_pad,thumb_distal` 세 영역을 읽는다.
17개 전체를 읽으려면 실행 인자 `tactile_regions:=all`을 지정한다.
기본 선택 밖의 영역은 hand_command_node에서 `미수신`으로 표시된다.
기본 청크 추가 대기는 0 ms이다. 이는 실제 영역별 수신 주기를 보장하지 않는다.
96 word 요청이 장치에서 지원되는지와 실제 수신 주기는 실기에서 확인해야 한다.

hand_command_node는 원시 배열을 `tactile_state[i].raw`에 저장한다.
판정용 값은 `values[j] = max(0, raw[j] - tactile_noise_floor)`이다.
기존 힘 기반 초기 파지 및 3초 대기 후, 접촉 합계가 충분한 새 프레임 3개의
평균을 각 영역의 기준 배열로 저장한다. `촉각 기준 준비` 로그를 확인한 뒤
받침대를 제거한다. 기준 준비 전 움직임은 기준에 섞일 수 있다.

기준과 현재 배열의 합계를 각각 B, S라 하고, 분포 변화는
`D = sum(abs(values[j]/S - reference[j]/B))`로 계산한다.
D >= 0.35 또는 합계가 현재 비교 기준 대비 30% 이상 감소하면 추가 조임 후보이다.
분포 변화 또는 합계 감소 조건이 새 프레임 2개 이상에서 최소 0.15초 지속되면 해당 손가락에 추가 조임 명령을 발행한다.
수신 간격이 1초보다 길면 지속 판정을 초기화한다.
서로 다른 영역은 동시에 샘플링되지 않는다. 전체 이탈 중단 조건은 아래와 같다.

ROS 파라미터 기본값:
- `tactile_noise_floor`: 20 (원시값)
- `tactile_contact_sum`: 1000 (영역 합계)
- `tactile_change_threshold`: 0.35 (정규화 분포 차이, 0~2)
- `tactile_confirm_seconds`: 0.15

이는 실험용 초기 임계값이며 물체·접촉 부위별 검증이 필요하다.
분포 변화는 하중 재분배나 손 움직임으로도 생겨 실제 미끄러짐을 확정하지 않는다.
균일하게 압력만 증가한 경우 정규화 분포 차이는 거의 0이다.
점수 Q는 `max(D, tactile_change_threshold * max(0, 1-S/B) / 0.3)`이다.
추가 조임량은 `clamp(slip_step * Q / tactile_change_threshold, slip_step, slip_max_step)`이다.
`slip_step` 기본 0.01 rad, `slip_max_step` 기본 0.03 rad이다.
손가락별 누적 `slip_max_extra` 기본 0은 누적 제한 해제를 뜻한다.
양수로 설정하면 해당 rad까지 누적량을 제한한다. URDF 관절각 상한
(엄지 굴곡 0.5864, 나머지 굴곡 1.4381 rad)으로 실제 명령 증가량을 제한한다.
엄지 회전 1.0 rad는 유지하며 손바닥은 직접 조임에 연결하지 않는다.

추가 조임 시 해당 손가락의 최근 수신 분포를 다음 비교 기준으로 저장한다.
`slip_settle_seconds` 기본 0.20초 후, 새로운 분포 변화가 2프레임 이상에서
0.15초 지속되면 다시 조인다. 초기 기준용 3프레임 수집은 반복하지 않는다.
처음 접촉했을 때의 소실 기준은 보존한다. 대기 중에도 접촉 소실은 감시한다.
조임이 일으킨 분포 변화와 실제 미끄러짐의 구분은 실기 검증이 필요하다.
실제 반응 시간은 촉각 수신 간격에 따라 길어진다.
한 영역의 감소로 해당 손가락을 영구 차단하지 않는다.
시작 시 무접촉 5프레임에서 측정점별 최댓값을 저장한다.
`max(0, raw - 무접촉최댓값 - 20)`의 합계 <= 100 및 최댓값 <= 20이면
무접촉 수준으로 판단한다. 0으로 돌아오지 않는 잔류값도 비교할 수 있다.
무접촉 수준 영역은 추가 조임을 건너뛰며 접촉 복귀 시 다시 판단한다.
보정 필수 영역은 `tactile_calibration_regions` 기본
[index_pad, middle_pad, thumb_distal]이다. 모두 보정되기 전 파지 명령을 보류한다.
따라서 실행 시 물체가 손에 닿지 않게 두고 `촉각 무접촉 보정 완료`를 확인한 뒤
물체를 배치한다. 초기 파지는 그 이후 자동 진행된다. 보정은 무접촉임을
자동 확인하는 기능이 아니므로 접촉 상태로 시작하면 잘못된 기준이 저장된다.
서로 다른 손가락 2개 이상에 기준이 존재하며, 모든 기준 영역에서 최근 1초 이내
새 프레임 2개 이상이 거의 0이고 그 상태가 0.3초 지속되면 전체 추가 조임을
중단한다. 이 전체 중단은 노드 재시작까지 유지한다. 이미 모터에 보낸 각도를
되돌리거나 손을 펴는 기능은 아니다. 한 영역만 기준이 있으면 전체 이탈을 확정하지 않는다.
관절 상태 수신이 500ms 이상 끊기면 추가 조임 명령을 발행하지 않는다.

실제 명령 발행 시 `미끄러짐 발생 → 추가 조임` 로그를 출력한다.
이 표현은 촉각 분포 조건을 만족했다는 뜻이며 미끄러짐의 독립적 실측은 아니다.
초기 파지 힘 범위 120~150 및 3초 대기는 그대로 유지한다.


## 2026-11-19: 촉각 통신 우선순위 조정

- `tactile_period_ms` 기본값 20 → 0 ms: 청크 완료 후 인위적인 추가 대기 제거.
- `tactile_feedback_period_ms` 기본값 100 ms (20~200 범위): 촉각 활성화 시
  힘·각도 읽기를 각 통신 루프마다 반복하는 대신 별도 간격으로 수행한다.
- 촉각 비활성화 시 기존처럼 매 루프에서 힘·각도 읽기.
- 명령 쓰기 확인은 모든 루프에서 유지. 한 연결에 병렬 요청하지 않는다.
- 실제 힘·각도 갱신 간격은 100ms에 통신 스케줄 지연이 추가될 수 있다.
- 기존 설정과 비교하려면 `tactile_period_ms:=20 tactile_feedback_period_ms:=20`.
- 기본 세 영역과 판정/조임 설정은 유지. 수신 주기 개선 정도는 실기에서 측정해야 한다.
- 변경된 드라이버를 적용하려면 하드웨어 노드를 포함한 real.launch 재시작이 필요하다.


## 전체/개별 추가 조임 비교

`slip_all_fingers` 기본 true: 감지 영역과 무관하게 다섯 굴곡 관절에 동일한
목표각 증가량을 보낸다. 각자의 기존 목표각에 더하며, 엄지 회전은 고정한다.
어느 관절 상한에도 걸리지 않는 공통 증가량을 사용하며, 한 관절이 상한이면
전체 추가 조임을 멈춘다. 무접촉 보정 및 전체 이탈 중단 조건은 유지한다.
전체 대상의 추가 조임 후 대기와 비교 기준을 함께 갱신한다.
`--ros-args -p slip_all_fingers:=false`로 기존 개별 제어를 선택할 수 있다.


## 2026-11-19: 손가락별 미세 접근 및 동시 힘 도달 확정

- 초기 파지 1초 판단 주기는 유지.
- 힘 < 100: 목표각 +0.015rad (기존 접근 증가량).
- 100 <= 힘 < 120: +0.001rad 미세 조임.
- 120 <= 힘 <= 180: 현재각 유지. 전체 도달 전에는 영구 정지하지 않고 매번 재판정.
- 힘 > 180: -0.001rad 미세 풀림.
- 같은 판단 시점에 엄지 굴곡·검지·중지·약지·소지가 모두 120~180이면
  다섯 목표각을 현재각으로 고정하고 전체 정지를 확정.
- 이후 기존처럼 힘 재확인 없이 각도 유지 및 3초 대기 후 촉각 감시로 전환.
- 동시 도달은 최신 JointState로 같은 제어 콜백에서 확인한다는 뜻이며,
  하드웨어 내부 센서들이 정확히 같은 순간 샘플링했다는 뜻은 아님.
- 엄지 회전, 무접촉 보정 및 전체 추가 조임 모드는 유지.
- 수정 전 백업: experiments/tactile_slip/backups/hand_command_node_before_simultaneous_grasp_20261119.cpp.
